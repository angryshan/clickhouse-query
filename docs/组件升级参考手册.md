# 组件升级参考手册

本文档用于后续同类组件（如 `clickhouse-query`、`clickhouse-ddl` 等）做运行时 / 依赖升级时的参考流程。  
以 **clickhouse-query → PHP 8.4** 这次实践为模板，后续升级可直接按清单执行。

---

## 1. 升级前先定目标

升级前先写清楚这 4 点，避免做到一半范围漂移：

| 项 | 说明 | 本次示例 |
|---|---|---|
| 目标版本 | 最低运行时要求 | `php >= 8.4` |
| 是否砍兼容 | 是否不再支持旧 PHP / 旧框架 | 砍掉 PHP 7.4、Hyperf 2.x |
| 命名空间 | 是否已统一 / 是否要改 | 统一 `TxAdmin\ClickHouseQuery\` |
| 验收标准 | 测什么算过 | PHPUnit 全绿 + 业务冒烟无明显问题 |

原则：

- Composer 的 `require.php` 要和真实代码能力一致，该强制就强制。
- 决定「不兼容旧版本」后，不要再留半套兼容分支（如 Hyperf 2/3 双路径），后续维护成本更高。
- **能不删就不删**：注释、PHPDoc（`@param` / `@return` / `@package` / `@author` 等）、说明性文案，只要不阻碍升级，一律保留；不要为了「看起来更干净」顺手删掉。

## 2. 标准升级清单

### 2.1 环境

1. 本机准备目标 PHP（当前推荐 `D:\phpstudy_pro\Extensions\php\php8.4nts`）。
2. 确认 `php -v`、`composer -V` 用的是目标 PHP。
3. Cursor / 终端若仍指向旧 PHP，用绝对路径或调整 PATH 后再继续。

### 2.2 composer.json

1. 调整 `"php": ">=x.y"`（或 `^x.y`）。
2. 核对 `autoload` / `autoload-dev` 与源码 namespace 是否一致。
3. 核对 `extra.hyperf.config`、`extra.think` 等框架注册类名。
4. 升级开发依赖：
   - PHP 8.4 → PHPUnit `^11.5`
   - php-cs-fixer 使用支持当前 PHP 的版本（如 `^3.64`）
5. `suggest` 只保留仍支持的框架包（例如 Hyperf 3 用 `hyperf/context`，不要再写 2.x `hyperf/utils`）。

### 2.3 代码扫描与改造

按优先级处理：

1. **PHP 新版本弃用项**（必须改）
   - 例：PHP 8.4 隐式可空 `Type $x = null` → `?Type $x = null` / `Type|null`
2. **类型声明补齐**
   - 接口、适配器、公开方法补 `mixed` / `: array` / 返回类型
3. **旧语法替换**（可顺手，但别扩大成重构）
   - `strpos !== false` → `str_contains`
   - `switch` → `match`（简单映射场景）
   - 构造器属性提升 / `readonly`
4. **框架适配层**
   - Hyperf：`ApplicationContext` 用 `Hyperf\Context\...`
   - ThinkPHP：按目标大版本 API 检查
5. **测试匿名类 / Mock**
   - 父类方法签名变更后，测试里的 override 必须同步，否则 Fatal

改造边界（重要）：

- 只改升级相关：语法兼容、类型、依赖、框架入口。
- **不要删除**仍有用的注释、PHPDoc、作者/包信息、业务说明。
- 重写某个文件时，把原有注释一并带过去，而不是写成「干净但没说明」的新文件。
- 确需删除时，只删已失效且会误导的内容（例如明确指向已废弃 API 的说明）。

### 2.4 文档与发布配置

同步改这些地方，避免业务照抄旧示例：

- `README.md` 环境要求、命名空间示例
- `publish/*.php` 配置样例中的 adapter / 类名
- 组件内其它 markdown 示例

### 2.5 代码风格与换行

本仓库约定 **CRLF**：

- `.php-cs-fixer.php` 中保持：`->setLineEnding("\r\n")`
- 改完代码后执行：

```bash
composer cs-fix
```

说明：

- **php-cs-fixer** 负责把 `src/` 统一成 CRLF + 风格规则
- **phpunit.xml** 不负责换行，只负责跑测试
- 本仓库 `.php-cs-fixer.php` 已关闭会误删 PHPDoc 的规则（如 `no_superfluous_phpdoc_tags`、`phpdoc_no_package`、`general_phpdoc_annotation_remove`），升级时保持这些关闭，避免注释被工具清掉

### 2.6 测试

```bash
php -v
composer update
composer test
# 或
php vendor/bin/phpunit -c phpunit.xml
```

关注点：

- 断言必须全绿
- PHPUnit 弃用提示（如 `@test` 注解）可后续改 `#[Test]`，不阻塞发版
- 若改了接口签名，重点回归 Mock / 匿名类测试

### 2.7 业务侧验证

1. 业务项目 PHP 已升到目标版本。
2. `composer update <组件名>`。
3. 全局搜旧 namespace / 旧类名。
4. 检查业务配置里的 `adapter` 等类名。
5. 冒烟：核心查询 / DDL / 分页等主路径跑一遍。

## 6. 踩坑记录（务必先看）

升级时优先「能跑在目标 PHP 上」，**默认不要改业务语义**。下面是实战踩过的坑。

### 6.1 语义：别为了「测绿」去改业务

| 现象 | 原因 | 正确做法 |
|---|---|---|
| 测试期望抛异常 / 有 `reset()`，实现却是返回空串 / 无此方法 | 测试与实现本来就不一致 | **改测试贴合现网语义**，不要反过来改生产代码 |
| 解密失败改成抛异常、空数组解密从 `false` 变成 `[]` | 为对齐「更理想」的测试 | 保持原返回值（如 `''` / `false`），除非产品明确要求破坏性变更 |

原则：PHPUnit 绿灯 ≠ 可以改契约。先问清楚是「只兼容新 PHP」还是「允许行为变更」。

### 6.2 PHP 8.4：`int` 属性不能直接吃 float

```php
// 旧写法在 8.4 可能 TypeError / 精度弃用
$this->id = ($this->id - $ret) / $mark; // / 得到 float
$mark = pow(2, $bit);                   // float
$this->id *= $mark;
```

只做兼容时，**就地强转即可**，不要借机重写算法或加一堆校验：

```php
$mark = (int) $mark;
$this->id = (int) (($this->id - $ret) / $mark);
$this->id = (int) ($this->id * $mark + $num);
```

### 6.3 依赖：没用到的包也会在 8.4 下炸弃用

例如 `illuminate/support` ^8 的 helpers 有隐式可空弃用。源码若根本没用到，**直接从 `require` 删掉**；若业务靠传递依赖装着，在业务项目里显式 `require`，不要绑在工具组件上。

### 6.4 php-cs-fixer：`$i++` 被改成 `++$i` / 双引号变单引号

`@PhpCsFixer` / `@Symfony` 规则集含 `increment_style`、`single_quote`，会把未使用返回值的 `$i++` 改成 `++$i`，并把无插值的 `"..."` 改成 `'...'`。语义通常不变，但 diff 吵。

在 `.php-cs-fixer.php` 里关掉：

```php
'increment_style' => false,
'single_quote' => false,
'phpdoc_types_order' => false,  // 不要把 array|null 改成 null|array
```

### 6.5 Windows + PowerShell：乱改文件编码会中文乱码

**禁止**用 PowerShell 的 `Set-Content` / `Out-File`（默认易变成系统代码页或 UTF-16）去批量替换 PHP 源码。

表现：注释变成 `����`，`git diff` 里中文全坏，文件体积也可能异常翻倍。

处理：

1. `git checkout -- <被写坏的文件>` 从版本库恢复
2. 用编辑器 / 本手册约定的工具改（Cursor Write/StrReplace，或 php-cs-fixer）
3. 改完用编辑器或 `Select-String` 确认中文注释仍可读

### 6.6 Composer 在 Windows 上的临时坑

- `vendor/composer/tmp-*.zip` **Permission denied**：本地写不进临时 zip，Composer 会回退 source，接着弹出 **GitHub Token**（公共包仍不要填）。  
  处理：`Ctrl+C` → 关掉占用该目录的 php/composer/杀毒/资源管理器预览 → 删掉半残目录后再装：

  ```powershell
  # 在组件根目录
  Remove-Item -Recurse -Force vendor -ErrorAction SilentlyContinue
  Remove-Item -Recurse -Force .composer -ErrorAction SilentlyContinue
  composer install --prefer-dist
  ```

  仍 Permission denied：检查盘符/目录 ACL（映射盘 `O:` 偶发只读或被其它用户锁住），或换到本机本地路径（如 `D:\...\xm-toolkit`）再装。
- 不要在「半残 vendor」上只 `composer update 某几个包` 且没有 lock：会报 partial update 错误；缺 lock 时用完整 `composer update` / `composer install`
- **镜像元数据不全**（常见腾讯云 `mirrors.cloud.tencent.com/composer`）：装 PHPUnit 11 时报  
  `phar-io/manifest` / `myclabs/deep-copy` 「只找到 `*-dev`，不满足 minimum-stability」。  
  先看源：`composer config -g repos.packagist.org.url`  
  处理：换源后清缓存再装（二选一）：

  ```powershell
  composer config -g repos.packagist composer https://mirrors.aliyun.com/composer/
  # 或官方：composer config -g repos.packagist composer https://repo.packagist.org
  composer clear-cache
  composer install
  ```

  用 `composer show -a myclabs/deep-copy` 确认 `versions` 里能看到 `1.13.4` / `1.14.0` 等稳定号，而不是只有 `1.x-dev`。

- **拉包卡在 `Token (hidden):` / GitHub OAuth**：多半是 dist 走 `api.github.com` **超时**后回退 source（git clone），并非真要装私有库。  
  **不要**在提示里输入 token（公共包不需要）。`Ctrl+C` 中断后：

  ```powershell
  # 继续用国内镜像，让 zip 走镜像 CDN，少打 GitHub
  composer config -g repos.packagist composer https://mirrors.aliyun.com/composer/
  composer config -g preferred-install dist
  composer config -g github-protocols https
  composer config -g process-timeout 600
  # 可选：少走 GitHub API
  composer config -g use-github-api false
  composer clear-cache
  composer install --prefer-dist
  ```

  若个别包仍失败，对该次安装可临时：`composer install --prefer-dist --no-plugins`，或换网络 / 代理后再装。

### 6.7 php-cs-fixer 与注释

本仓库已关闭会误删 PHPDoc 的规则（`no_superfluous_phpdoc_tags` 等）。升级时**保持关闭**，并坚持 CRLF：`->setLineEnding("\r\n")`。

## 7. 后续组件怎么用这份文档

升级其它 angryshan / tx-admin 组件时：

1. 先扫一遍「第 6 节踩坑」，尤其是语义边界与 Windows 编码。
2. 直接复制「第 4 节检查表」到任务备注 / MR 描述。
3. 按第 2 节顺序改：环境 → composer → 代码 → 文档 → cs-fix → test → 业务冒烟。
4. 只在「有新坑」时追加到第 6 节或案例后面，避免每个组件重复写一整份升级说明。


Remove-Item -LiteralPath "D:\phpstudy_pro\Extensions\php\php7.4.3nts" -Recurse -Force
