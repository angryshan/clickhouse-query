# 组件升级参考手册

本文档用于后续同类组件（如 `clickhouse-query`、`clickhouse-ddl` 等）做运行时 / 依赖升级时的参考流程。  
以 **clickhouse-query → PHP 8.4** 这次实践为模板，后续升级可直接按清单执行。

---

## 1. 升级前先定目标

升级前先写清楚这 4 点，避免做到一半范围漂移：

| 项 | 说明 | 本次示例 |
|---|---|---|
| 目标版本 | 最低运行时要求 | `php >= 8.4` |
| 是否砍兼容 | 是否不再支持旧 PHP / 旧框架 | 砍掉 PHP 7.4、Hyperf 2.x |
| 命名空间 | 是否已统一 / 是否要改 | 统一 `TxAdmin\ClickHouseQuery\` |
| 验收标准 | 测什么算过 | PHPUnit 全绿 + 业务冒烟无明显问题 |

原则：

- Composer 的 `require.php` 要和真实代码能力一致，该强制就强制。
- 决定「不兼容旧版本」后，不要再留半套兼容分支（如 Hyperf 2/3 双路径），后续维护成本更高。
- **能不删就不删**：注释、PHPDoc（`@param` / `@return` / `@package` / `@author` 等）、说明性文案，只要不阻碍升级，一律保留；不要为了「看起来更干净」顺手删掉。

## 2. 标准升级清单

### 2.1 环境

1. 本机准备目标 PHP（当前推荐 `D:\phpstudy_pro\Extensions\php\php8.4nts`）。
2. 确认 `php -v`、`composer -V` 用的是目标 PHP。
3. Cursor / 终端若仍指向旧 PHP，用绝对路径或调整 PATH 后再继续。

### 2.2 composer.json

1. 调整 `"php": ">=x.y"`（或 `^x.y`）。
2. 核对 `autoload` / `autoload-dev` 与源码 namespace 是否一致。
3. 核对 `extra.hyperf.config`、`extra.think` 等框架注册类名。
4. 升级开发依赖：
   - PHP 8.4 → PHPUnit `^11.5`
   - php-cs-fixer 使用支持当前 PHP 的版本（如 `^3.64`）
5. `suggest` 只保留仍支持的框架包（例如 Hyperf 3 用 `hyperf/context`，不要再写 2.x `hyperf/utils`）。

### 2.3 代码扫描与改造

按优先级处理：

1. **PHP 新版本弃用项**（必须改）
   - 例：PHP 8.4 隐式可空 `Type $x = null` → `?Type $x = null` / `Type|null`
2. **类型声明补齐**
   - 接口、适配器、公开方法补 `mixed` / `: array` / 返回类型
3. **旧语法替换**（可顺手，但别扩大成重构）
   - `strpos !== false` → `str_contains`
   - `switch` → `match`（简单映射场景）
   - 构造器属性提升 / `readonly`
4. **框架适配层**
   - Hyperf：`ApplicationContext` 用 `Hyperf\Context\...`
   - ThinkPHP：按目标大版本 API 检查
5. **测试匿名类 / Mock**
   - 父类方法签名变更后，测试里的 override 必须同步，否则 Fatal

改造边界（重要）：

- 只改升级相关：语法兼容、类型、依赖、框架入口。
- **不要删除**仍有用的注释、PHPDoc、作者/包信息、业务说明。
- 重写某个文件时，把原有注释一并带过去，而不是写成「干净但没说明」的新文件。
- 确需删除时，只删已失效且会误导的内容（例如明确指向已废弃 API 的说明）。

### 2.4 文档与发布配置

同步改这些地方，避免业务照抄旧示例：

- `README.md` 环境要求、命名空间示例
- `publish/*.php` 配置样例中的 adapter / 类名
- 组件内其它 markdown 示例

### 2.5 代码风格与换行

本仓库约定 **CRLF**：

- `.php-cs-fixer.php` 中保持：`->setLineEnding("\r\n")`
- 改完代码后执行：

```bash
composer cs-fix
```

说明：

- **php-cs-fixer** 负责把 `src/` 统一成 CRLF + 风格规则
- **phpunit.xml** 不负责换行，只负责跑测试
- 本仓库 `.php-cs-fixer.php` 已关闭会误删 PHPDoc 的规则（如 `no_superfluous_phpdoc_tags`、`phpdoc_no_package`、`general_phpdoc_annotation_remove`），升级时保持这些关闭，避免注释被工具清掉

### 2.6 测试

```bash
php -v
composer update
composer test
# 或
php vendor/bin/phpunit -c phpunit.xml
```

关注点：

- 断言必须全绿
- PHPUnit 弃用提示（如 `@test` 注解）可后续改 `#[Test]`，不阻塞发版
- 若改了接口签名，重点回归 Mock / 匿名类测试

### 2.7 业务侧验证

1. 业务项目 PHP 已升到目标版本。
2. `composer update <组件名>`。
3. 全局搜旧 namespace / 旧类名。
4. 检查业务配置里的 `adapter` 等类名。
5. 冒烟：核心查询 / DDL / 分页等主路径跑一遍。

## 4. 发版前检查表（可直接复制）

- [ ] `composer.json` 的 `php` 约束已更新
- [ ] autoload / ConfigProvider / suggest 已对齐
- [ ] 弃用 API / 隐式可空等已清掉
- [ ] 旧框架兼容代码已删除或明确保留原因
- [ ] 未误删注释 / PHPDoc / 说明性文案（没必要删的都保留）
- [ ] README / publish 示例已更新
- [ ] `composer cs-fix` 已执行（CRLF）
- [ ] `composer test` 全绿
- [ ] 至少 1 个业务项目冒烟通过
- [ ] 写清不兼容说明与回滚方式（旧 tag / 旧 commit）

## 5. 案例：clickhouse-query → PHP 8.4（已完成）

> 作为后续升级的对照样例，不是每次都要再写一份同类长文。

### 5.1 目标

- 强制 `php >= 8.4`
- 不再兼容 PHP 7.4 / Hyperf 2.x
- 保持 `TxAdmin\ClickHouseQuery\` 命名空间

### 5.2 实际改动摘要

- Composer / PHPUnit 11 / php-cs-fixer 升级
- 隐式可空、类型声明、`match` / `str_contains` 等改造
- Hyperf 适配器只走 `Hyperf\Context\ApplicationContext`
- README、publish 配置示例同步
- `composer cs-fix` 统一 CRLF

### 5.3 验证结果

| 项 | 结果 |
|---|---|
| PHP | 8.4.27 |
| PHPUnit | 11.5.57 |
| 测试 | 70 tests / 132 assertions 通过 |
| 结论 | 升级完成，当前暂无明显问题 |

### 5.4 业务升级注意

```php
'adapter' => \TxAdmin\ClickHouseQuery\Adapters\HyperfAdapter::class,
// 或
'adapter' => \TxAdmin\ClickHouseQuery\Adapters\ThinkPHPAdapter::class,
```

旧写法 `ClickHouseQuery\...`、Hyperf 2.x `Utils\ApplicationContext` 不可再用。

## 5.5 案例：clickhouse-ddl → PHP 8.4（已完成）

### 目标

- 强制 `php >= 8.4`
- 不再兼容 PHP 7.4 / Hyperf 2.x
- **保持**现有命名空间 `ClickHouseDDL\`（未强行迁到 `TxAdmin\`，避免扩大不兼容面）

### 实际改动摘要

- Composer / PHPUnit 11 / php-cs-fixer 升级；`suggest` 改为 `hyperf/context`
- 适配器 / 接口 / Handler：`getConfig(..., mixed $default = null): mixed` 等类型补齐
- Hyperf 适配器改为 `Hyperf\Context\ApplicationContext`
- `AdapterFactory` 使用 `match`；检测逻辑对齐 Hyperf 3
- `strpos` → `str_contains` / `str_starts_with`（小范围）
- README、publish 示例同步；注释与 PHPDoc 保留
- `composer cs-fix` 统一 CRLF

### 验证结果

| 项 | 结果 |
|---|---|
| PHP | 8.4.27 |
| PHPUnit | 11.5.57 |
| 测试 | 39 tests / 89 assertions 通过 |
| 结论 | 升级完成，当前暂无明显问题 |

### 业务升级注意

```php
'adapter' => \ClickHouseDDL\Adapters\HyperfAdapter::class,
// 或
'adapter' => \ClickHouseDDL\Adapters\ThinkPHPAdapter::class,
```

Hyperf 2.x `Utils\ApplicationContext` 不可再用；业务项目需 PHP >= 8.4。

## 6. 后续组件怎么用这份文档

升级其它 angryshan / tx-admin 组件时：

1. 直接复制「第 4 节检查表」到任务备注 / MR 描述。
2. 按第 2 节顺序改：环境 → composer → 代码 → 文档 → cs-fix → test → 业务冒烟。
3. 只在「有新坑」时追加一小节到本文「案例」后面，避免每个组件重复写一整份升级说明。
